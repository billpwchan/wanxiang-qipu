## 三层数据

| 层 | 来源 | 规模 | 文件 |
|---|---|---|---|
| 卡牌规则 | 官方卡牌接口快照（9/24 版本） | 85 英雄 · 98 效果牌 · 73 装备 · 258 天赋 · 19 棋手 | `research/raw-20260925/` → `site/dist/data/cards.json` |
| 榜单统计 | datawxq.com 公开榜单：顶尖棋手、v260924、近 7 天 | 19 位棋手、阵容家族、每个禁用阵营 | `research/v2/datawxq-20260925/` → `site/dist/data/meta.js` |
| 条件检索 | datawxq 大数据检索器：v260924、近 7 天、顶尖棋手 | 184,680 个终局，150+ 次条件查询 | `research/v2/explore/` → `site/dist/data/evidence.js` |

另外用到官方社区阵容接口（阵容码、导入次数，`research/v4/lineups/lineups.json`）。

榜单和检索器都是在浏览器里读取公开页面得到的（`scripts/fetch_meta.mjs`、`scripts/explore.mjs`），没有调用网站的签名接口。

## 平均名次

一局 6 人，第 1 名最好，所有人的平均是 3.5。页面上的标尺从第 1 名画到第 6 名，中间虚线是 3.5。

「前三」和「吃鸡」是进前三、拿第一的对局比例。

## 为什么路线不用「打成这套」的数字

榜单上的阵容统计的是**终局阵容**：一局结束时场上是什么，就算哪一套。

这样统计会系统性地高估每一套路线。想打韩信但没拿到韩信的人，终局场上不是韩信阵容，这局会被算到别的阵容里；留在「韩信阵容」里的，只有打成了的人。这是幸存者偏差：统计里每一套都像能进前三。

例子：玉环日落海倒转，终局是这套的对局平均第 2.9 名；主打这套的玉环（79% 的对局终局有司空震），全部对局是第 3.4 名。

## 路线的主数字

**棋手在第一回合就选定了**，之后不能换。所以「选了这个棋手之后的全部对局」包括打成的和半路崩掉的，是开局做出这个选择之后的真实结果。这和临床试验里的意向性分析（intention-to-treat）是同一个思路：按一开始的选择分组，而不是按最后的结果分组。

每条路线列了 1–3 个推荐棋手。主数字用的是其中**终局出现这套标志英雄比例最高的棋手**（`build_facts.mjs` 里的 `share`），比如香香的对局 68% 终局有公孙离，就用香香的全部对局代表大河开团射。

这个数字混着两样东西：棋手本身，和这个棋手打的所有路线。所以：

- 比例高（≥35%）时，页面写「X 的对局里 N% 在打这套，数字基本就是这套的表现」；
- 比例低时，页面写「X 什么都能打（只有 N% 的对局打这套），数字是它全部对局的平均」。

档位按这个数字分：≤3.20 首选，≤3.35 可以打，其余一般。

「打成这套时」的数字仍然显示在路线页上，只作为上限参考。孙小宾三分、钟馗韩信的定义比榜单的阵容家族更窄，「打成」用检索器的组合口径：孙小宾打成吕布（1,183 局，1.62）、韩信和钟馗同在场（1,738 局，2.37）。

## 成型后值得带 · 决赛别留

同一个主核的对局里，比较终局有这张牌和没有这张牌的平均名次：

- `d(Y|X)`：在有主核 X 的对局里，有 Y 比没 Y 的名次差（负数 = 更好）；
- `i(X,Y) = d(Y|X) − d(Y|全部)`：扣掉 Y 在所有对局里的平均表现。

Y 本身「后期才出现」的偏差（能留到终局的牌往往出现在打得好的对局里）在两项里都有，相减后大部分抵消，剩下的才算 X 与 Y 的配合。

- 值得带：出现 ≥300 局、`i ≤ −0.12`、且 `d < 0`；
- 别留：出现 ≥300 局、`i ≥ 0.20`、且 `d > −0.15`；
- 成型阵容里的牌不会出现在「别留」里（终局统计和成型阵容冲突时，以成型阵容为准）。

孙小宾三分、玉环倒转由单一棋手定义，搭档按这个棋手的对局算（≥150 局、`i ≤ −0.3` / `≥ 0.2`）。马可的对局混着养猪和吕布两套，猪八戒又出现在开团射里，两种算法都不干净，所以马可养猪不给搭档建议。

## 怕不怕撞车

6 个人共用一个牌池。同一局多一个对手也打同一个主核时，你的名次会变差，但这里面混着「对手的阵容本身强弱」。

所以用双重差分：

```
自己   = 有 1 个对手也打 X 时你的名次 − 没有对手打 X 时你的名次
对照   = 同样的对手情况下，打其他主核的人的名次变化
纯撞车 = 自己 − 对照
```

纯撞车 ≥0.25 名 → 很怕；≥0.12 → 有点怕；否则不怕。例子（`research/v3/deep-report.txt`）：嬴政 +0.40、周瑜 +0.28、蒙犽 +0.35、鲁班七号 +0.33；吕布 +0.03、司空震 −0.00。

## 阵容码与导入次数

路线页的「导入游戏」来自官方社区阵容：在 431 个不重复的社区阵容里找和这套成型阵容最像的一个（英雄集合的 Jaccard 相似度 ≥0.7；只差太乙真人、钟馗、海月这类决赛补位时 ≥0.55；推荐棋手相同时略加分）。页面会写出和这套相比多了、少了哪几张。

导入次数代表热门程度，不代表强度。「热门但别打」的 5 套阵容被导入了 26 万到 151 万次，顶尖对局里打成了也排在 3.7 名以后。

## 体检、机制链和每阶段买法

这些**没有对局数据**，来自卡面机制推导和社区打法：

- **体检**（成本、自动涨级、主核、弱点、没成型时，各 1–3 点，点越多越好）：从卡面推出。比如大河开团射全是 2–3 阶、每场开战免费给全队涨级，成本和自动涨级都是 3 点；孙小宾三分要 4–5 阶的小乔、周瑜、吕布，成本只有 1 点。
- **机制链**（「强在哪」三步）：卡面效果之间的因果链。
- **站位、拍卖出价上限、每阶段买哪几张**：机制推导 + 社区打法。

机制假设是在查数据之前写下的（`research/v3/hypotheses.md`：每条写明机制、可证伪的预测、用哪个查询检验），之后用检索器验证，结果在 `research/v3/deep-report.txt`。

「按卡面排强弱」单独用时错得很厉害：最早按卡面把姜导、镜排在前面，数据里它们是 3.58 和 3.73，低于平均。所以机制只用来解释「为什么」和找改进，「哪个强」由数据决定。

## 样本与偏差

- **只有顶尖棋手。** 数据来自 datawxq 的「顶尖棋手」分段，不代表所有段位。低段位里对手更弱，便宜、稳定的路线可能更占优，上限高的路线可能更难打成。
- **冷门棋手偏好。** 孙小宾、班叔、玉环、庄小鱼各只有约 2% 的人在用，用它们的人可能多是专门练这套的高手，数字偏好。嬴律、明先生、香香这些热门棋手的数字更可信。
- **时间窗口。** v260924 版本、近 7 天。游戏更新后所有数字都会变。
- **终局统计的遗留。** 「值得带」「别留」「怕不怕撞车」仍然基于终局阵容，已经用差分扣掉了大部分偏差，但不是随机实验。
- **公开接口可能落后客户端。** 卡牌规则来自官方接口快照，客户端热更新的数值可能还没同步。

## 怎么复现

```sh
python3 scripts/build_meta.py          # 榜单 → meta.js
python3 research/v3/build_evidence.py  # 检索器结果 → evidence.js
python3 research/v3/deep.py            # 联动、撞车、棋手适配的分析报告 → research/v3/deep-report.txt
node scripts/build_facts.mjs           # 三份数据 + plan.js → facts.js（控制台会打印每条路线的数字）
node scripts/verify-site.mjs           # 数据完整性
```

完整的数据更新流程见 [data-pipeline.md](data-pipeline.md)。
